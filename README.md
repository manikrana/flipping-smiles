# Kitabee

Personalized children's storybook platform. Authors create story templates in Studio; customers order personalized copies (with their child's name and photo) through the Store.

---

## Monorepo structure

```
apps/
  studio/       # Internal tool — story creation, character management, scene generation
  store/        # Customer-facing storefront — ordering, payment, PDF delivery
packages/
  core/         # Shared types and utilities
  pdf-engine/   # PDF generation from story + order data
supabase/
  migrations/   # Ordered SQL migrations (0001 → latest)
```

## Studio workflow

Studio is an internal tool used to build story templates before they go live in the Store. A complete story requires: characters → reference images → LoRA training → story pages → scene images.

### Step 1 — Create characters

Go to **Characters → New character**.

- **Name**: how the character will be referred to internally (e.g. "The Green Dragon")
- **Visual description**: physical appearance only — species, colors, proportions, distinctive features. No style keywords.
  - Use the **✦ Enhance** button to open a copy-paste instruction block. Paste it into Gemini or ChatGPT to get an image-generation-optimised rewrite, then paste the result back and hit Apply.
  - Good example: `small chubby emerald-green dragon, pale lime-yellow belly, round golden-amber eyes, two short ivory curved horns, tiny folded turquoise wings, smooth iridescent scales with darker green ridge along spine`
  - Bad example: `a green dragon` (too vague — model will invent different colors every time)
- Hit **Create character** to save.

### Step 2 — Generate reference images

On the character page, hit **Generate another** repeatedly until you have **5–10 reference images**.

- Each image is generated by flux-1.1-pro using the visual description
- Variations in angle and expression help the LoRA learn better
- **Delete any images that show wrong colors, wrong proportions, or off-style results** — consistency in the training set is more important than quantity
- Images are stored permanently in Supabase Storage (not expiring Replicate URLs)

### Step 3 — Train the LoRA

Once you have 5+ reference images, hit **Train character**.

- Training takes **10–15 minutes**
- You can navigate away — the characters list shows a spinning "Training" badge and updates automatically when done
- Each training run creates a fresh public Replicate model (named `kitabee-c{id}-{timestamp}`)
- When training completes, `lora_status` is set to `ready` and `lora_url` is stored in the DB
- If training gets stuck, use the **Stuck? Reset** link to clear the status and retrain

> Retrain whenever you update or delete reference images — the LoRA reflects only the images present at training time.

### Step 4 — Create a story

Go to **Stories → New story**.

- **Title, slug, description**: standard metadata
- **Hero description**: describes the child's placeholder character (e.g. `6-year-old boy, warm brown skin, large round hazel eyes, short wavy dark-brown hair, cobalt-blue t-shirt, olive-green cargo shorts`). Use **✦ Enhance** to optimise. This is prepended to every scene prompt.
- **Age range, price, languages**: configure per story
- **Cast**: add characters from the global library that appear in this story

### Step 5 — Write pages

Each page has:

- **Story text**: the narrative. Use `{{hero_name}}` where the child's name should appear.
- **Scene prompt**: describes the action and composition for that page's illustration. Use **✦ Enhance** to optimise.
  - Good example: `medium-wide shot, boy crouching near a large mossy rock, dragon peeking out from behind it, dappled sunlight through tall trees, low camera angle`
  - Bad example: `they meet in the forest` (no composition, no shot type)
- **Characters on this page**: select which cast characters appear in this scene. Only selected characters' LoRAs are applied.

### Step 6 — Generate scene images

On the story page, scroll to **Background scenes** and hit **Generate all**.

- Pages with trained LoRA characters use `flux-dev-lora` with the character's weights
- Pages with no trained characters fall back to `flux-1.1-pro` (text-only)
- Trigger words are automatically placed at the start of the prompt; LoRA scale is 1.0
- Images are stored permanently in Supabase Storage
- Use **Regenerate** on individual pages if a result is poor
- Use **Stuck? Reset** if the spinner freezes

### Tips for consistent characters

1. Write hyper-specific descriptions — exact color names matter (`emerald green` vs `green`)
2. Use the Enhance button for both character descriptions and scene prompts
3. Delete reference images that show color or proportion drift before training
4. Retrain after cleaning up reference images — the first train is rarely the best
5. Keep LoRA scale at 1.0; higher values (1.2+) cause the character to dominate or disappear

## Architecture

### Tech stack

| Layer | Technology |
|-------|-----------|
| Framework | Next.js 15 (App Router) |
| Database | Supabase (Postgres) |
| Storage | Supabase Storage (`assets` bucket) |
| Image generation | Replicate API |
| LoRA training | ostris/flux-dev-lora-trainer on Replicate |
| Scene generation (LoRA) | black-forest-labs/flux-dev-lora |
| Scene generation (text) | black-forest-labs/flux-1.1-pro |
| Reference generation | black-forest-labs/flux-1.1-pro |
| Monorepo | Turborepo + pnpm workspaces |

### Key database tables

| Table | Purpose |
|-------|---------|
| `cast_characters` | Global character library. Stores `lora_status`, `lora_url`, `trigger_word`, `lora_training_id` |
| `cast_character_references` | Reference images per character. URLs point to Supabase Storage |
| `stories` | Story templates with metadata and hero description |
| `story_pages` | Pages with story text, scene prompt, and generated `image_url` |
| `story_cast` | Which characters are in a story |
| `page_cast` | Which characters appear on each page (drives LoRA selection) |
| `orders` | Customer orders linking a story + child details |
| `order_pages` | Per-page personalised renders for each order |

### Storage layout (`assets` bucket)

```
reference-images/{characterId}/{uuid}.webp      # Character reference images
lora-training/{characterId}/training.zip        # Training image zip (input to trainer)
scene-images/{pageId}/{predictionId}.webp       # Generated scene backgrounds
```

### Scene generation flow

```
generateSinglePage(storyId, pageId)
  → getStoryContext()          # fetch hero description
  → getPageCharacterInfo()     # fetch page_cast → cast_characters (lora_url, trigger_word)
  → buildPrompt()              # trigger words first, then style + scene
  → startPrediction()
      if loraCharacters > 0   → flux-dev-lora (lora_weights + optional extra_lora)
      else                    → flux-1.1-pro (text only)
  → returns predictionId

pollBackgroundGeneration()
  → replicate.predictions.get()
  → on success: download image → upload to Supabase Storage → store permanent URL
```

### LoRA training flow

```
startLoraTraining(characterId)
  → fetch cast_character_references
  → download all reference images → zip
  → upload zip to Supabase Storage
  → replicate.models.create() → new public model (unique name per run)
  → replicate.trainings.create() → destination model
  → store lora_url + lora_training_id in DB (status: training)

pollLoraTraining(characterId, trainingId)
  → replicate.trainings.get()
  → on success: mark lora_status: ready (lora_url already stored at start)
```

### Prompt structure

```
{trigger_words}, Pixar 3D animated movie style, children's storybook illustration,
{hero_description}, {scene_prompt},
vibrant colors, cinematic lighting, highly detailed, 4k,
bottom 30 percent of image is a soft uncluttered area with minimal detail and gentle lighting,
no characters or busy elements in the lower third, clean space for text overlay
```

Trigger words (e.g. `CHAR3A2ABCCD`) are placed first so the LoRA activates at maximum strength.
